## 结论与范围

课题可以做。完整覆盖大场景系统、层次 LOD、异步预取和渲染器改造，工程风险偏高；收敛为“单 GPU、静态预训练场景、主存到显存的分块加载和 LRU 缓存”，难度中等偏上，适合本科毕设。这个结论以尽早跑通渲染后端、取得可用模型和完成分块正确性验证为条件。

不训练、不重新设计光栅化、不实现城市级系统、不开发磁盘流式存储系统、不集成 VR。主存可容纳工作场景；不能把主存到显存实验描述为磁盘到显存全流程流式加载。

最低交付为：一个可回放固定相机轨迹的真实渲染原型；全量加载、无跨帧保留的按需加载、LRU 缓存三组策略；若干缓存预算下的性能与图像质量实验；可复现说明、源程序和论文。先一个场景验证，再争取第二个场景，避免仅凭单场景推广结论。预取是扩展，失败或收益有限不影响基础系统的完整性，但需要如实报告。

## 平台选择

优先用 gsplat 的固定发布版本作为渲染后端，Python 负责预处理、块索引和调度。它提供张量渲染接口，便于实现与测量；它本身不是现成的缓存或流式管理器。Windows 官方提供部分预编译 wheel，先审查组合再安装。[官方仓库](https://github.com/nerfstudio-project/gsplat)、[Windows 安装说明](https://github.com/nerfstudio-project/gsplat/blob/main/docs/INSTALL_WIN.md)、[wheel 清单](https://docs.gsplat.studio/whl/gsplat/)。

Graphdeco 原版适合参考与演示，但不能假定已有完整动态加载接口。Nerfstudio 引入更多训练和框架依赖，当前阶段没有必要整套安装。Hierarchical 3DGS 已涉及按需 GPU 传输，但官方说明仍要求数据能放进主存，且带来层次结构和查看器工程负担，暂不作为主线。[Graphdeco](https://github.com/graphdeco-inria/gaussian-splatting)、[Hierarchical 3DGS](https://github.com/graphdeco-inria/hierarchical-3d-gaussians)。

`packed` 和 `radius_clip` 的作用不能写成场景流式加载。固定所有策略的 `packed`、SH 阶数、分辨率和裁剪参数，尤其避免用减少高斯或降低分辨率制造性能优势。[gsplat API](https://docs.gsplat.studio/main/apis/rasterization.html)。实际实现以固定 tag 对应代码为准，不照搬可能已变化的 main 文档。

## 设计中必须提前处理的难点

空间分块按高斯中心分配唯一归属，块包围盒根据高斯尺度、方向与约定的有限支持阈值扩大。高斯理论上有无限支持，所以“保守边界”仍是相对于明确阈值的近似，需用完整渲染对照确认质量。避免直接按中心做视锥判断。跨块数据若复制必须去重，防止 alpha 重复叠加。

可见块合并后进入同一次光栅化调用，保留全局深度排序；不采用各块独立渲染后直接覆盖。初版允许把驻留块打包到连续输入，记录该打包时间和额外 GPU 内存，不把它隐藏在渲染器之外。若每帧打包成为主要瓶颈，再考虑预分配缓冲区，不立即重写 CUDA 内核。

缓存预算按实际 GPU 张量字节数计算，主存保留原始数据。LRU 按帧批量请求：先确定并保护当前帧全部必需块，再淘汰其他块；不能边加载边淘汰同一帧刚刚需要的块。待 GPU 使用结束后才能复用存储或释放引用。PyTorch allocated、reserved 与进程显存分开记录，不能用一次 `empty_cache()` 或计数器下降证明数据管理已经正确。

如果单帧全部必需块大于预算，必须报告不可行点。最低版本采用阻塞加载、完整需求优先，不能悄悄丢块后宣称提速。若扩展采用允许临时缺块的非阻塞模式，需单独列实验，并逐帧记录缺块持续时间及 PSNR；不与阻塞完整模式混算。

预取只在必需数据就绪且有剩余预算时运行，不能挤掉当前帧数据；预测只用当前和历史相机信息。CUDA 异步传输需 pinned host memory、独立 stream 与事件同步，`non_blocking=True` 本身不能证明与渲染重叠。只有验证真实重叠后，论文才可使用该结论。

## 实验约定

| 策略 | 行为 | 作用 |
| --- | --- | --- |
| Full | 全量数据常驻显存 | 画面参考与显存充足时的性能参考；不强行套同一缓存预算 |
| Demand | 当前视图所需块按需加载，不保留跨帧缓存 | 测量按需传输的基础成本 |
| LRU | 相同块选择，加固定字节预算和跨帧保留 | 主要比较对象 |
| LRU+Prefetch，可选 | 相同预算、选择规则，加简单方向预测 | 检验预取收益与浪费 |

先固定 1280×720、一个工作场景和三种轨迹（平稳移动、往返、急转），参数须在后端跑通后确认。初始预算参考场景实测字节数，例如 25%、50%、75%，并先检查是否容纳单帧需求；没必要照抄 1/2/4GB。大于本机可用显存的全量参考标为 OOM 或不可行，不伪造测量。正常规模下先获取完整参考图像。

正式比较使用相同轨迹与固定步进，不让帧率高的策略获得不同相机样本。排除扩展编译和首次内核初始化，用固定预热段；每次重置缓存，正式重复至少 3 次，区分冷启动和暖运行。顺序轮换并记录插电状态、功耗模式、温度与背景应用。

每帧记录端到端墙钟帧时间、GPU 渲染时间、选择/打包时间、需求块命中数及总数、传输字节、实际驻留字节、峰值 allocated/reserved、缺块数。异步版本不能每帧用全局 synchronize 破坏重叠；用事件和最终汇总保证测量完整。总进程显存可辅以 NVIDIA 指标，WDDM 不支持的字段标明不可用。

分别报告启动至首帧时间、块加载就绪延迟、平均/p95 帧时间、卡顿帧比例（预先约定阈值如 33.3ms）、CPU→GPU 字节数、按块及按字节命中率。预取命中指“需求发生前已完成的预取”，另记未使用即淘汰的字节，不能把发起请求当成命中。

质量相对于同后端、同参数的 Full 图像逐帧测 PSNR，并抽取典型图像检查边界和闪烁；SSIM 可选。同源 Full 对照反映加载带来的质量变化，不等于对真实照片的重建质量评价。PSNR 约定 RGB [0,1]、相同背景、MSE=0 为 +inf。先给每帧值再汇总，避免仅挑完整加载后的帧。
