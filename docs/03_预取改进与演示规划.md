# 预取改进与可视化演示规划

2026-11-10 更新：固定方向、自适应预测范围与保守准入版本已完成初测。保守准入减少了相对固定方向的无效预取，普通 LRU 的尾延迟收益尚未稳定复现。实现、结果与复测见 [Playroom 负载与预取初测](07_Playroom负载与预取初测.md)。下一步关注上传提交开销与消融，后续接入可视化演示。

## 研究问题

在同一 GPU 缓存预算和相同画质约束下，能否比“固定距离、固定数量的方向预取”减少急转和速度变化时的无效传输，并降低加载等待及 p95 帧时间？

初步方案为**相机运动与加载成本感知的自适应预取**，三个组成部分按顺序增加，避免一下引入过多参数：

1. 根据最近若干帧的位置、视线和转角建立短期预测；运动稳定时适度延长预测范围，急转、停止或方向不确定时缩短。视线方向与平移方向分别处理。
2. 用历史实际传输时间估计各块的就绪成本，按“预计可见概率 × 屏幕贡献估计 × 可避免的加载等待 / 占用字节”排序候选块。优先级计算也计入 CPU 开销，不使用未来轨迹作预测输入。
3. 当前帧需求优先；在剩余缓存和传输配额内预取。方向变化后撤销未发出的过时任务；已在传输或 GPU 使用的缓冲区必须等事件完成，不能强行释放。

最小改进先只实现第1项（自适应预测范围），取得可解释结果后再增加成本与预算反馈。以上组件本身都是已有思想，不预先宣称首创；相关工作调研后再界定论文的具体改进点。若组合没有稳定收益，如实分析适用条件，不以增加算法名称代替实验。

## 对照与消融

主要对照为 LRU 无预取、LRU 固定方向预取、LRU 自适应预取。保证相同字节预算、同一块选择器、相同渲染参数和时间定义。

可行时分别关闭自适应预测范围、成本权重和预算反馈，检查每一项到底贡献了什么。参数在调试轨迹上选择，在独立轨迹上比较，禁止针对每条测试轨迹单独挑最优参数。

除了 p95 和平均帧时间，还记录按需等待、预取及时命中字节、错误预取字节、总传输字节、缓存峰值与图像质量。固定步进轨迹用于可重复的加载实验；异步预取若依赖实际时间，还要说明相机时间轴如何推进，不让较慢方法自动获得额外预取时间。两种计时模式需要分开报告。

本方案首先控制工作量，不要求训练预测模型或开发新的 CUDA 光栅化内核。若要论证传输与计算重叠，需要单独采集 CUDA event/分析器证据，不能仅根据 `non_blocking=True` 宣称成功。

## 演示目标

最终演示应能回放和暂停同一相机轨迹，切换策略和预算，并让观众看见场景、数据块状态和性能变化。自由移动相机可作演示功能；正式对比仍使用固定回放。

| 视图/控件 | 展示内容 | 说明 |
| --- | --- | --- |
| 场景画面 | 当前帧真实 3DGS 渲染 | 不自动降低分辨率隐藏卡顿 |
| 块状态图 | 必需、驻留、待加载、预取中、已淘汰 | 用空间包围盒或小地图，不必叠满主画面 |
| 运动提示 | 当前运动方向、预测方向/范围 | 解释急转时为何减少预取 |
| 指标曲线 | 帧时间、显存、传输量、命中/浪费 | 明确即时数据与历史数据 |
| 控制区 | 轨迹、播放/暂停、策略、缓存预算 | 改变策略后重置缓存，防止对比不公平 |

先实现简单验证图像和离线记录，再选择轻量交互查看器，不在环境配置阶段搭建复杂界面。正式测量关闭额外可视化或单独报告其开销；演示流畅度与性能测量分开。

## 完成顺序

1. 当前任务：配置 A 环境，真正调用 CUDA 光栅化，保存图像和版本报告。
2. 一个真实预训练场景 + 全量基线 + 固定轨迹。
3. 分块正确性、按需加载、LRU、指标。
4. 固定方向预取和自适应预测范围；再判断成本权重是否值得加入。
5. 消融/多轨迹实验及可视化演示，2027年3月力争冻结主要功能。

用户已批准 A 路线的环境下载与配置。更换方案、模型合集下载或额外大型工具链按实际需求另行说明，不重复要求批准已授权的 A 环境。
