# 系统设计与实现

这个原型研究显存预算受限时，怎样在 3D Gaussian Splatting（3DGS）渲染中减少等待数据的时间。输入是 Graphdeco 发布的 Train 和 Playroom 预训练场景及其相机参数。Python 和 NumPy 负责分块、视锥选块与运动预测，PyTorch 负责张量和 CUDA 流，gsplat 负责光栅化。 [场景来源与依赖](../MANIFEST.md)

## 从模型到一帧图像

1. **离线分块。** 读取 PLY 的中心、尺度、旋转、透明度和颜色参数，按最大轴尺度分带，再沿高斯中心跨度最大的轴递归切分。标准布局每块最多 2048 个高斯。载荷和包围盒索引分别保存在 `payload.npy` 和 `index.json`。 [空间分块代码](../scripts/spatial_blocks.py)
2. **确定必需块。** 每帧用相机视锥测试扩张后的块包围盒，为跨边缘的高斯保留余量。回放前检查单帧峰值需求能否装入预算。 [视锥选块与回放](../scripts/stream_blocks.py)
3. **加载并渲染。** 缓存按字节计量，先保护当前帧必需块，再按最近最少使用（LRU）顺序淘汰其他块来容纳需求缺失。把选中的块拼接后，交给一次 gsplat 光栅化，统一排序和混合。 [缓存与渲染](../scripts/stream_blocks.py) · [渲染参数](../scripts/render_settings.py)
4. **预取未来数据。** 先向主 CUDA 流提交当前帧渲染，再预测未来视野，用另一条流上传候选块。帧末等待渲染和已提交的预取完成。 [预取与帧循环](../scripts/compare_prefetch.py)

计时中的上传发生在 CPU 主存与 GPU 显存之间。场景块缓存预算限制常驻块载荷，整进程显存还包含拼接副本、上传暂存区、光栅化中间张量和分配器保留空间。

## 短期预取

`short_only` 用最近的相机位姿估计平移和转动，按运动稳定程度预测 0、1 或 2 帧。预测两帧时取两个视野的候选块交集，减少只在一次预测里出现的块。每帧预取额度为 16 MiB，准入时保护当前帧必需块。新预取的块以低优先级加入缓存，实际被访问后才提升优先级。

批量路径将候选块集中到页锁定主存，合并 H→D 提交，再在显存中复制成可独立淘汰的块。向量化将多个预测视锥的选块合并为 NumPy 矩阵运算。实验用 CUPTI 核对拷贝与渲染内核的重叠，并单独记录设备内复制。 [实验与取舍](experiments.md)
