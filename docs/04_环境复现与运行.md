# 环境复现与运行

本项目采用 A 路线：项目内 CPython 3.10.11 x64、PyTorch 2.4.1+cu124、gsplat 1.5.3+pt24cu124、NumPy 1.26.4。最终是否通过以 `reports/smoke/result.json` 和实际图像为准，不以安装成功替代渲染验证。

## 日常运行

在项目根目录打开 PowerShell。

```powershell
.\run_python.ps1 --version
.\verify_environment.ps1
```

无需激活 Conda。`run_python.ps1` 固定使用 `tools/python310/python.exe`，启用 UTF-8、禁用用户级 site-packages，将临时目录与 pip 缓存放在项目内，结束后恢复当前进程对应环境变量。

单独重新渲染测试图：

```powershell
.\run_python.ps1 scripts/smoke_render.py --output-dir reports/smoke
```

生成 PNG、PPM 和 JSON。图像为本地生成的 576 个高斯，不是预训练场景；单次 GPU 计时仅检查后端工作，不是论文性能结果。

## 固定依赖与离线重装

已下载 wheel 放在 `downloads` 与 `downloads/wheels`。锁文件包含 20 个运行依赖的版本和散列，其中 packaging 和 setuptools 由实际后端加载路径补齐。

```powershell
.\run_python.ps1 -m pip install --no-index --find-links downloads --find-links downloads/wheels --only-binary=:all: --require-hashes -r requirements-lock.txt
```

不要直接执行不带版本的 `pip install -U`，也不要使用系统 Python 安装这些依赖。`reports/dependency_plan.json` 为安装前解析结果，`reports/install_report.json` 为实际安装结果，`reports/dependency_wheel_manifest.json` 保存 PyPI 依赖的来源和已校验散列；两个 CUDA wheel 各有来源与 SHA256 JSON。

## 便携运行时的边界

运行时从 Python 官方 embeddable ZIP 解压，不运行系统安装器、不修改注册表、全局 PATH 或 GPU 驱动。标准库、固定依赖和项目路径由 `python310._pth` 明确指定，未使用普通 venv。

Python 官方嵌入式分发不是通用开发安装，常规 pip 管理不属于其标准使用方式；这里将依赖作为项目运行时的一部分固定管理，并实际验证导入、GPU 运算与渲染。新增需要编译或完整开发环境的包时要重新评估，不能把该目录当作任意升级的通用 Python。官方说明见 [Windows embeddable package](https://docs.python.org/3.10/using/windows.html#the-embeddable-package)。

Python 3.10 已结束支持的取舍见下载审核清单。此环境用于本地毕设实验，不替换日常开发环境。若移动项目目录，需要使用系统 Python 重新执行 `scripts/prepare_runtime.py` 生成绝对项目路径；已有两个 bootstrap 文件时不会重新下载。所有依赖和大文件仍可继续复用。

本阶段没有安装完整 CUDA Toolkit/MSVC，没有下载14GB模型合集。下一阶段再核实预训练场景来源与使用条件。
